# Brain Atlas Game ("Where in the Brain?")

GeoGuessr-style neuroanatomy quiz: show a brain slice, name a region, the player
clicks, points depend on distance. Meant for studying for neuroanatomy exams.
Owner is a biology student (comfortable with Python/R, new to web dev): keep tools
simple, explain technical choices briefly, and keep code readable and commented.

## Working agreements
- Plan first, wait for OK, then build milestone by milestone. Commit at each milestone.
- **Never guess API endpoints, IDs, or file formats.** Verify with a real request or
  the docs and show the evidence. If something behaves unexpectedly, say so; don't
  silently work around it.
- After each milestone: give exact run commands and what to click to test.
- Scoring and pixel → region lookup are what decide correctness; keep them pure
  functions with unit tests.

## Layout
```
pipeline/            Python: download Allen data, export slices (run once)
  build_atlas.py     the script (downloads → checks → exports)
  atlas_lib.py       pure helpers (ontology flattening, label remap, region stats)
  tests/             pytest
  cache/             downloaded raw files (gitignored)
web/                 Vite + TypeScript static site, no framework, no backend
  public/data/       GENERATED by the pipeline, committed (so the site builds without Python)
  src/types.ts       JSON shapes shared with the pipeline
  src/tree.ts        region-tree helpers (isWithin, descendantMask)
  src/labelmap.ts    .bin decoding, pixel lookup, click→slice coords, nearest target point
  src/scoring.ts     distance → points, parent partial credit
  src/game.ts        choosing rounds
  src/data.ts        fetching the data files
  src/render.ts      canvas drawing
  src/storage.ts     best score in localStorage
  src/main.ts        page wiring (screens, events)
```

## Rebuild the data
```
cd pipeline
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python build_atlas.py     # downloads ~37 MB once into cache/, rewrites web/public/data/
pytest
```
Then commit `web/public/data/`.

## Data sources (verified 2026-11-22)
- Ontology: `https://api.brain-map.org/api/v2/structure_graph_download/1.json`.
  Nested tree with `id, acronym, name, color_hex_triplet, parent_structure_id, children`;
  1327 structures; `success: true` at top level, tree under `msg[0]`.
- Annotation: `https://download.alleninstitute.org/informatics-archive/current-release/mouse_ccf/annotation/ccf_2017/annotation_25.nrrd`
  (uint32, gzip, shape 528×320×456, 25 µm). 10/50/100 µm versions exist alongside.
- Background: `.../mouse_ccf/average_template/average_template_25.nrrd` (uint16, same
  shape). This is a two-photon autofluorescence average, **not** Nissl.
- `brainglobe-atlasapi` (v3.1.0) has `allen_mouse_*` and `allen_human_500um` but heavy
  dependencies. Not used for mouse; reconsider for the human phase.

## Known quirks (verified on the real data)
- **NRRD header lies about orientation.** It says `space: left-posterior-superior`,
  but arrays are stored as (AP, DV, LR): axis0 anterior→posterior, axis1
  dorsal→ventral, axis2 left→right. `build_atlas.py:check_orientation` checks this
  on the anatomy (MOB before CB, Isocortex above HY, 96.4 % L/R mirror symmetry)
  and exits if it ever fails. Known issue: Allen community forum, BICCN
  cell-locator issue #48.
- **Structure ids go up to 614454277** (128 ids > 2^24), so raw ids can't be packed
  into RGB PNGs. We map ids to a compact `index` (position in structures.json, fits
  uint16) and store label maps as raw `.bin` files.
- **Tree depth ≠ region size** (CB depth 2, TH/HY 4, Isocortex/HPF 5, CA1 8), so
  difficulty uses hand-picked lists, not raw depth.
- The python.org macOS Python has no root certificates by default
  (`CERTIFICATE_VERIFY_FAILED`); downloads use `certifi`. Never disable verification.
- `apMm` is distance from the front of the CCF volume, **not** bregma.
- Several Allen colours are grey (VS `#AAAAAA`, fiber tracts `#CCCCCC`) and vanish on
  the grey slice, so the answer is revealed in a fixed cyan (`render.ts:HIGHLIGHT`)
  with a solid outline, not in the Allen colour.
- Browsers report clicks in whole CSS pixels (Chrome: `clientX` truncated). At the
  default size that is ≈0.5 slice px ≈ 0.013 mm. This is expected, not a bug.
- Some acronyms equal the name ("fiber tracts"); the prompt hides the acronym then.

## Data format (web/public/data/)
- `structures.json`: array; entry i has `index == i`. Entry 0 = "outside brain"
  (annotation value 0). Fields: `index, id, acronym, name, parentIndex, depth, color`.
  Parents come before children.
- `coronal_XXX.bin`: label map for slice at AP index XXX; raw **little-endian uint16**,
  row-major; value at pixel (x, y) is `data[y * width + x]`; values are structure
  *indices*. x = left→right, y = dorsal→ventral.
- `coronal_XXX.png`: 8-bit grayscale template, same width/height as the .bin. One
  contrast window (0.5–99.5th percentile of brain voxels) for all slices.
- `slices.json`: `{source, slices: [...]}`; each slice has `id, plane, index, apMm,
  width, height, mmPerPixel, image, labels, targets.easy, regions`. `regions` is keyed
  by index with `areaPx` and `centroid` [x, y], **aggregated up the tree**.

## Game rules (M1)
- Easy targets: Isocortex, OLF, HPF, CTXsp, STR, PAL, TH, HY, MB, P, MY, CB,
  fiber tracts, VS; only on slices where the region is ≥ 0.5 mm².
- 10 coronal slices, evenly spaced over AP positions where brain area ≥ 25 % of max.
- Distance = click to nearest point of any pixel within the target (either hemisphere),
  measured to pixel edges (click inside → 0). Points = round(1000·exp(−d / 0.75 mm)).
- Partial credit: click inside the target's parent → at least 250, unless that parent
  is root or grey (depth ≤ 1).
- 10 rounds; best score in localStorage key `brain-atlas:best-score:easy`.
